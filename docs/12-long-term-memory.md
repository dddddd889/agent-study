# 第 12 步：跨会话长期记忆

> 第 9 步的 `.sessions/<id>.jsonl` 是**每会话的原始流水**,那不是记忆。这一步加**跨会话长期记忆**:把对话里值得长期记住的**事实/偏好/决定**蒸馏成一份全局记忆,**跨会话注入上下文** —— 而不是把原始历史搬来搬去。

## 记忆 ≠ 流水

| | 原始流水(第9步) | 长期记忆(本步) |
|---|---|---|
| 内容 | 一字不差的对话 | 蒸馏后的事实/偏好/决定 |
| 范围 | 每会话一份 | **全局一份,跨所有会话** |
| 用途 | 续聊**同一段**对话 | 让 agent 在**任意新会话**里记得你 |
| 存储 | `.sessions/<id>.jsonl` | `.memory.md`(bullet) |

实测:进程 A 说"我叫小明,喜欢蓝色" → 退出;进程 B(**全新会话,没续聊那段流水**)问"我叫什么" → 答出"小明、蓝色"。靠的就是 `.memory.md` 被注入系统提示。

## 谁来写记忆:一个专门的「记忆 agent」

没有让主 agent 调 `remember` 工具(那依赖它"记得调"、还污染主提示),而是用一个**专门的记忆 agent**([memory.ts](../src/memory.ts) 的 `extractMemory`):

- 形态:一个**聚焦的 LLM 调用**(无工具,像 `summarize()`);
- 输入:**当前 `.memory.md` + 本次对话**;
- system:「提取值得长期记住的事实/偏好/决定,合并进已有记忆,**去重、保持简洁**,输出完整记忆」;
- 输出:**合并去重后的完整记忆** → 覆盖写 `.memory.md`。

好处:**主 agent 零改动、上下文干净**;读现有记忆+对话**重写**,天然去重(优于 append 式堆积)。

## 关键:后台跑,不阻塞主 agent

记忆 agent 是额外的 LLM 调用,**绝不能卡住主对话**。做法([cli.ts](../src/cli.ts)):

- **每轮结束后 fire-and-forget**:`updateMemory()` **不 await** —— LLM 调用是网络 I/O,不占事件循环,CLI 立刻回到提示符;
- **单飞(single-flight)**:一次没跑完不重叠启动;被跳过也没事,记忆 agent 每次读**全量历史**,下次会补上;
- **吞错**:后台 promise `catch` 掉,记忆失败不影响主对话;**空结果不覆盖**(避免清空记忆);
- **退出 flush**:`/exit` 时 `await` 在飞的 + 补跑一次,纳入最后一轮(`kill` 终端仍可能丢最后一次,best-effort);
- 记忆 agent **不绑主回合的 abort signal**(它是后台独立任务,中断的是当前回复)。

## 读取/注入

会话开始时读 `.memory.md`,拼进系统提示:`系统提示 = 基础提示 + "\n\n[长期记忆]\n" + 记忆`。会话中后台更新的新记忆**不刷新本会话 system**(本会话的事实还在 live 历史里,记忆是给**下次**会话用的)。

## 命令

- **`/memory`**:查看当前 `.memory.md`;
- 后台更新**静默**(不每轮刷屏);清空/编辑(`/forget`)留 TODO。
- 路径默认 `.memory.md`(已 gitignore),可用 `AGENT_MEMORY_FILE` 覆盖(测试隔离)。

## 测试(`bun test`)

- [tests/memory.test.ts](../tests/memory.test.ts):`write→read` 往返(临时文件 `AGENT_MEMORY_FILE` 隔离);`extractMemory` 用 FakeLLM(据 system 含"记忆"返回合并结果)验证产出。
- 后台不阻塞/单飞是 CLI 接线 → **PTY 实测**:第一进程退出后 `.memory.md` 写入;第二进程(新会话)记得名字/偏好。

## 这在"上下文工程"里的位置

长期记忆 = **把历史蒸馏成精华、跨会话复用** —— 和第 11 步摘要压缩同源(都是"蒸馏"),但:摘要是**会话内**省 token,记忆是**跨会话**沉淀。两者都属于"该挪的挪/该留的留"。
