# apply_patch：内容定位（非行号）+ 全或无原子应用

## 决策

新增 `apply_patch` 工具，用 Codex 风格补丁一次性完成**跨多文件、含增删文件**的编辑。补丁由**模型生成**，我们负责解析 + 应用。两条关键设计：

1. **靠内容定位，不靠行号**：每个 hunk 还原成「旧块（上下文行 + `-` 行）→ 新块（上下文行 + `+` 行）」，在文件当前内容里**精确、唯一**命中旧块再替换；同一文件多个 hunk 在内存副本上**按序应用**。补丁头 `@@ -l,c +l,c` 的行号**忽略**。
2. **全或无原子**：先解析整个补丁 + 定位所有 hunk + 校验所有前置条件，任何一处失败就**整补丁拒绝、一个字节不写**；全部通过才一起落盘。

## 为什么

**补丁是模型生成的，必然有瑕疵**（上下文抄少、缩进差一格、尤其行号算不准）。设计目标不是「完美 diff」，而是「**容忍不完美的 diff**」：

- 用 unified diff 的**行号硬定位**（`git apply` 那套），模型一旦算错行号、或前面 hunk 增删导致后面行号漂移，就整块错位——所以否掉行号，改**内容定位**（模型不擅长数行，但擅长给出周围几行上下文）。
- 内容定位天然**免疫行漂移**：后一个 hunk 在前一个改完的内容里按内容再找，绝对行号无关紧要。
- 唯一失败模式是「内容命中 0 次或多次」→ 触发原子失败、给出可诊断报错，模型据此**改补丁重试**，而不是悄悄改错地方或半途留下坏状态。

## 边界

- **格式非 Claude 原生**：我们跑 Claude 模型，而 `*** Begin Patch` 是 Codex 格式，Claude 不天生熟——所以工具描述里**带一个完整示例**教它生成。
- **前置条件**：`Update`/`Delete` 要求先 `read` 过该文件（read-before-edit）；`Add` 要求目标不存在（防覆盖）。
- **与 edit_file/write_file 共存**：单处小改用 `edit_file`、单文件新建/重写用 `write_file`、跨文件批量/原子用 `apply_patch`。
- **rename/move 留 TODO**（先用删+增凑）；补丁需装进一次 tool_use（受 `max_tokens`）。
