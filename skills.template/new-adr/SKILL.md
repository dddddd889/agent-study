# 起草一篇 ADR

为一个已定下的设计决策，按本仓库 `docs/adr/` 的规范起草一篇 ADR。

## 步骤

1. `glob docs/adr/*.md` 列出已有 ADR，确定下一个编号（四位、递增，如已有到 0014 则新的是 0015）。
2. 挑最近一两篇 ADR（如编号最大的）`read_file` 读一遍，对齐格式、语气、详略。
3. 与用户确认这篇 ADR 的**决策主旨**（若 ARGUMENTS 里已给就用它）；不清楚就先问一句。
4. 按下面结构起草，用中文，文件名 `docs/adr/<NNNN>-<kebab-英文短名>.md`。
5. 写完提醒用户：如该能力在 `docs/roadmap.md` 有条目，别忘了把 🚧 改成 ✅ 并补步号。

## 结构

```markdown
---
Status: accepted
---

# <决策一句话标题>

## 决策
<做了什么。分点列关键设计选择，每点标注对应的 Q 或维度。>

## 为什么这样
<权衡与理由。为什么不选别的方案。呼应既有不变量。>

## 边界与考量
<已知局限、留作 TODO 的部分、实现时踩到的坑。>

## 落地
<涉及哪些文件、核心改动；指向 PRD / CONTEXT 术语。>
```

## 规矩

- 术语一律用 `CONTEXT.md` 里定义的词，别引入同义词漂移。
- 若决策与某条已有 ADR 相矛盾，**显式指出**（「与 ADR-0007 相矛盾——但值得重议，因为…」），不要悄悄覆盖。
- 只起草文件内容，是否写盘/提交听用户的。
